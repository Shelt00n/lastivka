# Ластівка: короткий опис рішення

## 1. Обраний застосунок і що відтворено

**Telegram** (мобільний клієнт iOS): ним я користуюся щодня. Відтворено мобільну веб-версію рівно на **5 сторінок**:

| # | Сторінка | Сценарії |
|---|----------|----------|
| 1 | `/login` | вхід, реєстрація, демо-вхід |
| 2 | `/` Чати | папки, пошук + глобальний пошук, закріплення / без звуку, непрочитані, банер тихих годин |
| 3 | `/chat/:id` Чат | надсилання, відповідь, редагування, видалення, реакції, «друкує…», ✓/✓✓, історія, кнопки ботів |
| 4 | `/chat/:id/info` Профіль | @username, біо, місцевий час і тихі години, учасники групи, сповіщення |
| 5 | `/settings` Налаштування | профіль, **тихі години**, тема, активні сеанси, вихід |

Модальні вікна (нове повідомлення / нова група, меню повідомлення) не є окремими сторінками.

Дизайн повторює Telegram iOS (світла тема зі світло-зеленими бульбашками на «шпалерах» з візерунком) і Telegram Night Blue (темна тема). Новій функції дано власний акцентний колір: спокійний фіолетовий «нічний».

## 2. Нова функція: «Тихі години»

**Проблема.** У Telegram можна вимкнути сповіщення в себе, але відправник не знає, що зараз у тебе третя ночі, а повідомлення все одно приходить і висить «непрочитаним». Особливо болить у розподілених командах (Київ / Токіо / Нью-Йорк).

**Рішення.**
- Користувач задає вікно (наприклад, 23:00–08:00) у своєму часовому поясі.
- Відправник ще до надсилання бачить банер: «Kenji відпочиває · там 00:42. Доставимо завтра о 00:30 (там 07:30)».
- Повідомлення зберігається з `deliver_at` і **фізично не існує для отримувача** до кінця вікна: його немає у списку, лічильниках, пошуку, відповідях і SSE-подіях. Планувальник раз на 5 с доставляє такі повідомлення; часом повідомлення стає момент доставки.
- Відправник може надіслати «Терміново», а відкладене повідомлення — «Надіслати зараз», відредагувати або скасувати.
- Отримувач, який не спить, бачить «N повідомлень чекають до 08:00 · Отримати зараз» (без імен і тексту).
- Зміна вікна чи вимкнення функції переносить або одразу доставляє відкладені повідомлення.
- Приватність: точне вікно й часовий пояс видно іншим, лише якщо ввімкнено «Показувати мій місцевий час».
- Логіка часу спільна для сервера й клієнта (`src/shared/quietHours.ts`), тож банер і сервер завжди згодні щодо часу доставки. Вікна через північ і переходи DST покрито тестами.

## 3. API-інтеграція

**Власний REST + SSE API** (Hono), з яким працює клієнт:
- REST: `/api/auth/*`, `/api/me`, `/api/chats`, `/api/chats/:id/messages` (курсорна пагінація), `/api/messages/:id` тощо;
- реальний час: **Server-Sent Events** (`/api/events`), окремий потік на вкладку, події адресуються конкретним користувачам після перевірки прав;
- клієнт: TanStack Query (кеш, інвалідація), оптимістичні оновлення (надсилання з «годинником», реакції, редагування), зіставлення SSE-відлуння з оптимістичною копією без дублів, перепідключення з backoff і ресинхронізацією після розриву.

**Зовнішні API** (через ботів, із сервера, а не з браузера):
| Бот | API | Ключ |
|-----|-----|------|
| Погода | Open-Meteo Geocoding + Forecast | не потрібен |
| Курси НБУ | `bank.gov.ua/NBUStatService` | не потрібен |
| Вікі | Wikipedia OpenSearch + REST Summary | не потрібен |

Спільний клієнт `createJsonClient`: жорсткий тайм-аут 6 с, TTL-кеш (погода 10 хв, курси 30 хв), **валідація відповіді zod-схемою** (зовнішні дані недовірені), зрозумілі повідомлення про помилки замість падіння. Запити з сервера не передають стороннім сервісам IP чи сесію користувача.

## 4. Захист даних

| Загроза | Захід |
|---------|-------|
| Чужі чати | Єдиний шлюз `requireMember` / `requireVisible`; нечленам чату відповідаємо 404 (не 403), щоб не можна було перебирати id |
| Відкладені повідомлення | Видимі лише відправнику на рівні SQL-запитів і SSE |
| Паролі | scrypt (N=16384) з випадковою сіллю, `timingSafeEqual`; для невідомого логіна теж рахуємо хеш, щоб час відповіді не видавав існування акаунта |
| Сесії | 256-бітний випадковий токен у **httpOnly**-cookie, `SameSite=Lax`, у продакшені `Secure` + префікс `__Host-`; у БД лише SHA-256 токена; ковзне завершення через 30 днів; вихід і «Завершити сеанс» інвалідують одразу, зокрема живий SSE-потік |
| CSRF | Зміни лише з того самого Origin і лише `application/json` (HTML-форми не пройдуть) + SameSite |
| XSS | React-текст без `dangerouslySetInnerHTML`; посилання тільки `http(s)`, `rel="noopener noreferrer nofollow"`; CSP `default-src 'self'` |
| Ін'єкції | Лише параметризований SQL; поля оновлення профілю — з фіксованої мапи; zod `.strict()` відкидає зайві поля |
| Перебір / спам | Ліміти: вхід (10/5 хв на логін+IP, 50/5 хв на IP), реєстрація, надсилання (30/10 с); ліміт тіла 32 КБ |
| Витік через API | Публічний профіль формує тільки `toPublicUser`; тести перевіряють, що у відповідях немає хешів і токенів |
| Заголовки | CSP, `X-Content-Type-Options`, `X-Frame-Options`, HSTS у продакшені (Hono `secureHeaders`) |

## 5. AI-агенти та пайплайн

**Ролі:**

1. **Claude Code (Claude Opus 5.5), головний агент** у Claude Desktop. Прочитав ТЗ, спроєктував архітектуру, написав сервер, клієнт і тести, запускав typecheck, тести й збірку, а також сам тестував застосунок у вбудованому браузері (телефонний viewport, скриншоти, мережа, консоль).
2. **Агенти-рецензенти** в репозиторії (`.claude/agents/`), які запускає той самий Claude Code:
   - `security-auditor`: шукає дірки в авторизації, витоки відкладених повідомлень, XSS і CSRF; кожну знахідку має довести тестом, який падає;
   - `test-engineer`: пише й підтримує тести за пріоритетами (доступ → тихі години → auth → зовнішні API → утиліти);
   - `qa-tester`: проходить усі сценарії в браузері з телефонним viewport і звітує таблицею pass/fail.
3. **`CLAUDE.md`**: спільні правила для всіх агентів (архітектура, обов'язкові правила безпеки, правила тестів, «не додавати нових сторінок»).
4. **CI (GitHub Actions)**: на кожен push / PR запускає typecheck → тести → збірку → Docker-збірку. Код агента не потрапляє в main, доки CI не зелений.

**Пайплайн:** ТЗ → план (головний агент) → реалізація шарами (shared → server → тести сервера → web) → `npm run check` → QA в браузері → рецензенти (`security-auditor`, `qa-tester`) → виправлення → CI → людське рев'ю й відео.

> **Чесно про те, що вже зроблено:** реалізацію, тести й браузерну QA-перевірку виконав головний агент.
> Агенти-рецензенти описані й готові до запуску. Їхні результати слід додати сюди після запуску.

## 6. Тести

**107 тестів, 7 файлів, усі зелені** (`npm test`, ~2 с). Чому саме вони: тестую те, де помилка найдорожча і найменш помітна оком.

| Файл | Що перевіряє | Чому |
|------|--------------|------|
| `tests/server/access.test.ts` (12) | чужий користувач не може прочитати, змінити, відреагувати, процитувати чи отримати SSE-подію з чужого чату; тільки свої повідомлення можна редагувати; у відповідях немає хешів; приховування вікна тихих годин; пагінація | головна властивість месенджера: приватність листування |
| `tests/server/quietHours.test.ts` (13) | вся нова функція через HTTP: утримання, невидимість для отримувача, доставка рівно в момент закінчення вікна, «Терміново», «Надіслати зараз», «Отримати зараз», перенесення при зміні вікна, жодного утримання в групах, ботах і «Збереженому» | нова функція = нова поверхня для витоків і помилок у часі |
| `tests/shared/quietHours.test.ts` (15) | вікна через північ, межі, інші часові пояси, **перехід на літній / зимовий час** (Київ, Нью-Йорк), «неіснуючий» час у DST-проміжку | часові розрахунки найлегше зламати й найважче помітити вручну |
| `tests/server/auth.test.ts` (17) | scrypt, httpOnly-cookie, однакова відповідь для «немає користувача» / «невірний пароль», rate-limit, вихід інвалідує сесію, завершення чужої сесії неможливе, CSRF (чужий Origin, text/plain), ліміт тіла, заголовки безпеки | захист облікових записів |
| `tests/server/bots.test.ts` (26) | парсер запитів курсів, конвертація, формат погоди, ланцюжок geocoding → forecast, Вікі, **тайм-аут, HTTP-помилка, невалідна відповідь, кеш** зовнішнього API | інтеграція не має падати від чужого API |
| `tests/web/format.test.ts` (15), `messages.test.ts` (9) | українські відмінки й множина, дати як у Telegram, групування бульбашок, роздільник непрочитаних, `linkify` не створює `javascript:`-посилань | те, що бачить користувач у кожному рядку |

Тести сервера використовують SQLite у пам'яті та **керований годинник** (`createTestApp(startAt)`), зовнішні API підмінено, тож тести детерміновані й не потребують мережі.

## 7. Як перевіряли результати роботи AI

- **Тести як контракт:** тести на доступ, тихі години й auth написано одразу після сервера, ще до фронтенду; далі кожну зміну проганяли через typecheck і тести.
- **Типи:** суворий TypeScript (`strict`, `noUncheckedIndexedAccess`) для сервера й клієнта окремо.
- **Смоук-тест реального сервера** через `curl`: вхід, список чатів, відповідь бота з живим курсом НБУ, 403 для чужого Origin.
- **Браузерна QA** (телефон 375×812, світла й темна теми, десктоп): усі сценарії зі скриншотами, перевірка консолі й мережі. Знайдено й виправлено:
  - конфлікт портів API і Vite у dev (`PORT` від середовища): API в dev тепер слухає `API_PORT`;
  - ініціали «К«» для назв у лапках;
  - неоднозначний час доставки («о 00:30» → «завтра о 00:30 (там 07:30)»);
  - вітання ботів у демо опинялися вище за особисті чати;
  - верстка рядка тихих годин у профілі й перемикачів.
- **Продакшен-перевірка:** збірка → один процес віддає SPA, CSP не блокує застосунок, вхід і реальний час (повідомлення від `demo2` через `curl` з'являється без перезавантаження).
- **Людське рев'ю:** читання диффу, перевірка UX на власному телефоні, запис відео.

## 8. Час і обмеження

**Час:** ≈ 45 хв роботи агента (проєктування, код, тести, QA, документація) + _[ваш час на рев'ю, деплой і відео]_.

**Обмеження:**
- Один інстанс: SQLite і шина SSE в пам'яті. Для горизонтального масштабування потрібні Postgres і Redis pub/sub (або `LISTEN/NOTIFY`).
- Немає медіа, голосових, дзвінків, push-сповіщень (Web Push) і E2E-шифрування. Шифрування в дорозі забезпечує HTTPS хостингу, на диску дані не шифруються.
- Вхід за логіном і паролем замість телефону з SMS.
- Тихі години працюють лише для особистих чатів: у групах повідомлення не утримуються.
- Rate-limit зберігається в пам'яті процесу.
- Безкоштовний хостинг без диска скидає базу при перезапуску (демо-дані створюються знову).
- Боти залежать від безкоштовних публічних API (частково згладжено кешем і тайм-аутами).

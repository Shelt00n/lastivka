# Ластівка — звіт до тестового завдання

Ластівка — мобільна веб-копія Telegram з новою функцією «Тихі години»: повідомлення, надіслане вночі, чекає на сервері до ранку отримувача.

**Посилання:** [застосунок](https://lastivka-unxz.onrender.com) · [код на GitHub](https://github.com/Shelt00n/lastivka). Вхід: `demo` / `lastivka-demo` (другий акаунт — `demo2`) або власна реєстрація.

## API-інтеграція та захист даних

Клієнт (React) працює з власним REST API на Hono, нові повідомлення приходять у реальному часі через SSE, дані зберігаються в PostgreSQL. Три боти беруть дані із зовнішніх API: погода (Open-Meteo), курси валют (НБУ) і Вікіпедія.

Захист: паролі хешуються (scrypt), сесія зберігається в httpOnly-cookie, кожен запит перевіряє, що користувач є учасником чату. Є захист від CSRF і XSS, ліміти запитів, а база закрита для зовнішніх підключень.

## AI-агенти

Основний агент — Claude Code (Claude Opus 5.5): спроєктував архітектуру, написав код і тести, перевірив застосунок у браузері та підготував деплой. Ще три агенти-рецензенти налаштовані в репозиторії (безпека, тести, ручна QA); у цій роботі їхні чеклисти виконував основний агент. Кожен push перевіряє CI на GitHub Actions: типи → тести → збірка.

## Тести

112 юніт-тестів (Vitest), усі проходять. Тестував найризикованіше: доступ до чужих чатів, «Тихі години» разом із переходом на літній час, вхід і сесії, стійкість до збоїв зовнішніх API. Саме там помилка найдорожча й найменш помітна оком.

## Як перевіряли роботу AI

Кожну зміну проганяв через TypeScript, тести, збірку й CI, а застосунок перевіряв у браузері на екрані телефона. Так знайшли й виправили кілька помилок: конфлікт портів, втрату даних на безкоштовному хостингу (перейшли на PostgreSQL) і вразливість спільних демо-акаунтів.

## Час і обмеження

Близько 1,5 години роботи агента плюс час на рев'ю й відео. Обмеження: один сервер без масштабування, немає медіа, дзвінків і push-сповіщень, безкоштовна база Render діє 30 днів.
